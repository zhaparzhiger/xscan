# ForteBank Datathon 26AI — выявление нарушений кассовой дисциплины по видео

Локальный AI-сервис: принимает видеозапись работы кассира (`.mov`, ракурс сверху, без звука), находит визуально наблюдаемые признаки возможных нарушений и показывает проверяющему тип события, таймкод, кадры-доказательства, описание и ссылку на норматив РК.

> Результат — подсказка для проверки человеком, а не юридическое или дисциплинарное заключение.

## Ключевые требования кейса

- Веб-интерфейс + серверная часть, публичный URL.
- Публичный API с ключом в заголовке `X-API-Key`:
  - `POST /api/v1/analyze` — загрузка `.mov` (поле `file`), в ответ `job_id`;
  - `GET /api/v1/jobs/{job_id}` — статус (`processing` / `done` / `failed`) и результат.
- Вердикт на всё видео: `no_violation` или `violation`; для каждого нарушения — `type`, `timecode_sec`, `description`, 1–3 кадра `evidence_frames` (JPEG base64).
- Обработка одного видео — не более 5 минут.
- **Полностью локально**: никаких облачных LLM/мультимодальных API, после загрузки весов интернет не нужен. Только open source с лицензией, допускающей коммерческое использование.
- Только визуальный анализ: без звука, без распознавания лиц.
- Нормативная база — только акты РК (НБРК, adilet.zan.kz); нельзя выдумывать ссылки.
- Приоритет: минимум ложных срабатываний, пропуск нарушения недопустим.
- Тестовое видео будет снято под другим ракурсом, возможны типы нарушений, которых нет в обучающей выборке.

Подробный разбор — в [docs/requirements.md](docs/requirements.md).

## Быстрый старт

Датасет организаторов (`open/videos/*.mov` + `open/open_labels.xlsx`) лежит у каждого локально, в git он не попадает.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/pip install -r requirements-ml.txt --extra-index-url https://download.pytorch.org/whl/cpu
cp .env.example .env            # поменять API_KEY

# 1. разметка: xlsx -> data/labels.csv (нормализует X/Х в именах файлов)
.venv/bin/python ml/prepare_labels.py --xlsx ~/Downloads/open/open_labels.xlsx --videos ~/Downloads/open/videos
# 2. CLIP-признаки всех видео (долго, один раз; кэш в data/features)
.venv/bin/python ml/extract_features.py --videos ~/Downloads/open/videos --aug
# 3. обучение (секунды) + отчёт кросс-валидации
.venv/bin/python ml/train.py
# 4. сервис
./scripts/run.sh                # http://localhost:8000
./scripts/smoke_test.sh ~/Downloads/open/videos/X-1.mov    # проверка API как у жюри
./scripts/tunnel.sh             # публичный https URL (cloudflared)
```

## Архитектура

```
 Браузер (app/static)          Жюри (curl, X-API-Key)
        │ /ui/*                      │ /api/v1/*
        └──────────┬─────────────────┘
                   ▼
        FastAPI (app/main.py) ── jobs.py: очередь, статусы на диске (data/jobs/*.json)
                   │  фоновый поток
                   ▼
        pipeline/analyze.py
          1. video.py        выборка кадров, 4 fps
          2. features.py     CLIP ViT-B/32 → эмбеддинг кадра + признаки окна ±1 с
          3. detector.py     P(нарушение) на каждый момент  ← models/detector.joblib
          4. events.py       сглаживание, порог, пики → события (таймкод = пик)
          5. detector.classify  тип события               ← models/types.joblib / zero-shot
          6. rules/registry  описание + НПА               ← rules/violations.yaml
          7. video.py        1–3 JPEG-кадра → base64
```

**Почему так.** Видео всего 42, поэтому обучать большую нейросеть с нуля бессмысленно, она переобучится. Мы берём замороженную предобученную модель CLIP, которая работает как «глаза», и обучаем поверх неё маленький классификатор (логистическую регрессию). Он учится за секунды на CPU, GPU не нужен.
- **Устойчивость к другому ракурсу** (финальное видео снимут с другого угла): аугментации (отражение, кроп, перспектива) в `extract_features.py --aug`. CLIP сам по себе довольно устойчив к ракурсу.
- **Пропуск недопустим** (FAQ п.16): `train.py` выбирает порог так, чтобы recall на кросс-валидации был 1.0, а уже потом минимизирует ложные срабатывания.
- **Незнакомые типы нарушений** (FAQ п.9): если классификатор не уверен, событие получает тип `generic` («признаки возможного нарушения»).
- **Без выдуманных ссылок** (критерий 4): пункт НПА выводится только при `verified: true` в `violations.yaml`.
- **Локальность**: веса скачиваются один раз (`scripts/download_models.py`), дальше интернет не нужен. В Docker они запекаются в образ.

## API (раздел 10 ТЗ)

| Метод | Путь | |
|---|---|---|
| POST | `/api/v1/analyze` | multipart, поле `file` (.mov) → `{"job_id", "status"}` |
| GET | `/api/v1/jobs/{job_id}` | `processing` / `done` / `failed` + `verdict`, `violations[]` |
| GET | `/health` | состояние моделей |

Ключ передаётся в заголовке `X-API-Key` (переменная `API_KEY` в `.env`). Веб-интерфейс ходит на `/ui/*` без ключа и получает расширенные поля: уверенность, интервал, ссылку на правило, график.

## Структура

```
app/            сервис (FastAPI + пайплайн + UI)
  rules/violations.yaml   типы нарушений ↔ нормативы (заполняет ресёрч)
ml/             подготовка разметки, признаки, обучение
scripts/        запуск, туннель, smoke-тест, прогон по датасету
data/           (в .gitignore) labels.csv, признаки, загрузки, задачи: всё только локально
models/         (в .gitignore) обученные модели — передавать файлом, не через git
```
