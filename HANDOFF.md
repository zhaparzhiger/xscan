# HANDOFF — XScan (ForteBank Datathon 26AI)

Файл для того, кто продолжает работу (человек или другой Claude) на другом компьютере. Здесь то, чего нет в коде:
что выяснено, что пробовали, что не сработало и что делать дальше. Секретов в репозитории нет.

## Что это
Локальный AI-сервис: видео кассы (`.mov`, ракурс сверху, без звука) -> вердикт `violation` / `no_violation`,
таймкоды, кадры-доказательства, описание, норматив РК. API `POST /api/v1/analyze`, `GET /api/v1/jobs/{id}`,
ключ `X-API-Key`. Лимит 5 минут на видео. Всё локально (облачные AI-API = дисквалификация). Подробности: `docs/requirements.md`.

## Как поднять на новой машине
```bash
git clone <repo> && cd fortebank-cashier-ai && git checkout zhiger
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt                       # Linux/Mac: .venv/bin/pip
.venv/Scripts/pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128   # GPU (или /cpu)
.venv/Scripts/pip install open_clip_torch "transformers>=4.57" bitsandbytes accelerate qwen-vl-utils scikit-learn
python scripts/download_extra_models.py          # Qwen3-VL-4B, SigLIP2, SAM2.1 в models/ (~9 ГБ)
cp .env.example .env                             # заполнить: API_KEY, UI_USERS (scripts/make_user.py), SESSION_SECRET
export XSCAN_VIDEOS=~/Downloads/open/videos      # датасет организаторов, в git его НЕТ
.venv/Scripts/python -m uvicorn app.main:app --port 8010    # порт 8000 может быть занят
```
Датасет (`open.zip`: `open/videos/*.mov` + `open/open_labels.xlsx`) положить локально; он только для хакатона, не публиковать.
Разметка: `python ml/prepare_labels.py --xlsx .../open_labels.xlsx --videos .../videos` -> `data/labels.csv`.
Железо, на котором всё считалось: Windows 11, RTX 4060 Laptop 8 ГБ. Qwen3-VL-4B в 4 бита занимает всего ~2.9 ГБ.

## Главные находки по данным (важно, это не видно из кода)
1. **Дубликаты:** `X-4 == X-47` (один файл, нарушения на 57 и 68 с) и `X-5 == X-48` (норма). В `labels.csv` они лежат как разные ролики.
   Всегда использовать `ml/labels2.py::unique_videos()` (40 уникальных видео, 21 с нарушением, у X-4 два таймкода). Иначе утечка в кросс-валидации.
2. **Нормальные и нарушающие ролики — почти одинаковые сценарии.** Отличие в мелком состоянии объектов. Пример: пара X-28 (нарушение) и X-29 (норма):
   кассир уходит из кабинета; в нарушении на ноутбуке остаётся открытая таблица (экран белый), в норме экран заблокирован (тёмный).
3. **Сценарии нарушений** (по просмотру кадров вокруг таймкода, таймкод = момент события):
   - кассир ушёл от стола/из помещения, оставив ценности или разблокированный ноутбук: X-11, 15, 22, 24, 26, 28
   - сейф оставлен открытым: X-13, X-20
   - посторонний в кассе (клиент/второй человек входит): X-1, 2, 4(+47), 18, 30, 38
   - личные вещи/еда/питьё на рабочем месте: X-40, 44, 46
   - прочее: X-17 (инкассатор с зелёным мешком), X-32, 33, 34
   Три разных ракурса камеры в датасете (кабинет снят с трёх позиций).
4. Qwen3-VL умеет находить рамки (экран ноутбука, сейф, стол) на кадре любого из трёх ракурсов — `ml/ground.py` -> `data/boxes.json`. Это работает хорошо.

## Что пробовали и какие метрики (кросс-валидация по видео, GroupKFold)
| Подход | Результат |
|---|---|
| CLIP ViT-B/32 + логрегрессия (исходный каркас `ml/train.py`) | recall 0.64, FPR 0.80 — почти случайно |
| SigLIP 2 (весь кадр + 4 тайла), позы KeypointRCNN, их комбинации (`ml/experiment*.py`) | frame-AUC 0.64–0.69, video-AUC 0.35–0.48 |
| Qwen2.5-VL-3B, открытый вопрос «что видно» (`ml/vlm_probe.py`) | 170 с на запрос, повторяет подсказку из промпта («сейф открыт») — ненадёжно |
| Qwen3-VL-4B, вопросы да/нет по кадрам (`ml/vlm_qa.py`, `ml/eval_vlm_qa.py`) | AUC по вопросам 0.40–0.65; video-AUC 0.47 |
| Состояния объектов по рамкам: экран/сейф/стол/люди (`ml/state_features.py`, `ml/eval_state.py`) | лучшие признаки: движение 0.73, смена вида сейфа 0.68; модели ~случайно (video-AUC 0.33) |
| Пики движения как кандидаты событий | топ-3 пика попадают в ±3 с от таймкода в 86% (случайно 60%); топ-1 — 32% (случайно 29%) |
Вывод: общие эмбеддинги и зеро-шот VLM не различают нарушение и норму; данных (21 нарушение в 5 сценариях) мало для обучения.

## Принятая стратегия (на усмотрение, дальше следовать ей)
- ТЗ: «пропуск недопустим, ложных срабатываний как можно меньше». Реалистично на этих данных — режим **высокий recall**:
  сервис выдаёт события-кандидаты с таймкодами и кадрами (подсказка проверяющему), честно без заявлений о точности.
- Прочие критерии зависят не от качества детекции: **нормативная база РК** (15 баллов). Статус в `docs/norms.md`: постановления № 14/2020
  и № 231/2019 прочитаны, пункты сверены с текстом и привязаны в `app/rules/violations.yaml`. Ничего не выдумывать.
  Остальное: интерфейс, архитектура, локальность.
- Идеи, которые ещё не доделаны: правило «ноутбук остался разблокированным при уходе» (экран белый + кассир ушёл), сейф по вырезке.
  Bot API и агент движения (`scripts/agent_motion.py`) есть с коммита e239dfb.

## Состояние на 18.10.2026 (VLM-режим, интерфейс)
- **Анализ идёт через мультимодальную модель (VLM) на Vertex AI**: `ANALYZER=vlm`, `GOOGLE_APPLICATION_CREDENTIALS=<путь к JSON сервисного аккаунта>` в `.env`, нужен `google-auth`.
  ВНИМАНИЕ: в `docs/requirements.md` облачные API = дисквалификация. Пометка «согласовано с жюри» в коде ничем не подтверждена — выяснить до сдачи.
  Интерфейс сам пишет «Анализ: VLM» и не обещает «всё локально», когда включён облачный режим (`isCloud()` в `design/js/app.js`).
- **Замер** `ml/eval_vlm.py` (40 уникальных видео): нашёл 19 из 21 нарушений, ложные тревоги на 8 из 19 нормальных, таймкод в ±3 с: 10 из 19,
  в среднем 26 с на ролик (максимум 53 с). Промпт подбирался по этим же видео, так что на закрытом тесте будет хуже.
  Вариант `VLM_MEDIA_RESOLUTION=HIGH VLM_VIDEO_WIDTH=768 VLM_VIDEO_FPS=4`: те же 19 из 21, ложных 7 из 18, таймкод 14 из 19,
  но в среднем 40 с и до 174 с на ролик плюс таймаут на X-14 — не включали. Основные ложные тревоги: «посторонний» в нормальных роликах
  (X-3, 5, 19, 35, 37, 39), где на кадрах так же входит человек и садится напротив кассира — разницы с X-1 глазом не видно.
- Скрипт замера пишет `data/eval_report.json` (с кадрами), его показывает страница «Замер» (`GET /ui/eval`). Повторный запуск берёт ответы из кэша
  `data/vlm/<модель>-<tag>/`. Последний запуск перезаписывает отчёт — после экспериментов перегенерировать базовый: `python ml/eval_vlm.py --tag base`.
- «Обзор» и «История» теперь на реальных данных: `GET /ui/jobs` (имя файла и время в `data/jobs/<id>.meta`), старый отчёт открывается с видео
  (`GET /ui/jobs/{id}/video`). Демо-цифр и плашек «демо-данные» больше нет; описания агентов говорят, что агент ищет, без выдуманных моделей и метрик.
- Ещё макет: страница «Обучение» (имитация процесса и лога) и деление на агентов при проверке. На деле один запрос к VLM, агенты загораются по типу найденного нарушения.
- Дизайн: тема всегда светлая `1torg`, иконки Phosphor duotone (MIT) вшиты в `design/js/icons.js`, аватарки агентов — `design/img/agents/*.svg`
  (DiceBear Notionists by Zoish, CC0). Кэш статики сбрасывается через `?v=` в `design/index.html`.
